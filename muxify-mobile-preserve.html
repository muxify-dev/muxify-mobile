Debrief · branch muxify-mobile-preserve · uncommitted work · 2026-11-25

A page in the Web View now stays loaded when you leave it. Close Page or the closure of its Topic releases it.

Did the work do what was asked? Mostly. The cause is found, the fix is in the code, and the unit tests pass (2066 tests). Hide and close are now different actions. Pages are released on Close Page and when their Topic closes, and each Topic has its own page.

What differs: the check on the simulator was not done. The disk was full (639 MB free) and the Release build stopped. An e2e suite for the form, navigation and Topic cases is written but did not run.

1 · The page was lost because the WebView lived inside the screen that Back unmounts

Example: you type draft-a in a form on a page, tap Back, and open the Topic again. Before, the Web View screen held the WebView. Back unmounted the screen, and the page ended with it. The Place kept only the URL and the scroll, so the page loaded again from the start with an empty form. sessionStorage and the page's script state were also lost. Now the WebView lives in a provider above the navigator, and only its native view moves into the screen.

The provider is mounted in src/app/_layout.tsx:24, inside AttachProvider, so it is also above the navigator. Each page is rendered in a <Portal hostName="live-page-N"> (src/browser/live-pages-context.tsx:185). The screen renders <LivePageHost>, a PortalHost (live-pages-context.tsx:127, src/app/web-view.tsx:256). react-native-teleport moves the native WKWebView into the host without a remount. When the host goes, it moves the view back under the screens, out of sight.

2 · Hiding keeps the page; only four events release it

  • Close Page: web-view.tsx:143–147 calls leave(), then kept.pages.close(page.id). The toolbar button is at web-view.tsx:245. The Attach's leaveTab clears the Tab from the Place.
  • Tab gone: when a restore finds that the Host no longer lists the Tab, web-view.tsx:194 closes the page.
  • Owner gone: on each Listing, live-pages-context.tsx:81–88 calls prune. It releases a page whose Topic is not open, or whose Session the Host does not have (live-pages.ts:87–93). This can also happen while the page is shown: then the Terminal Screen takes its place (web-view.tsx:149–155).
  • Host deleted: src/components/hosts-section.tsx:82 calls releaseHost.

The Place and the Live Page are separate. A Window pick in the Title Sheet clears the Tab from the Place, so opening the Topic again shows the Terminal Screen. But the pick only hides the page: if you open the same Tab again, you get the same page with its form text. Only the four release events end a page.

A page opened after a Listing was received is not pruned by that Listing (page.openedAt >= readAt, live-pages.ts:90), because its Topic can be newer than the Listing. A Disconnect releases nothing. An app restart loses all Live Pages, and then the Place loads the page again at its URL and scroll.

3 · Each Topic has its own page of the same Tab, so text cannot go from one Topic to another

Example: Tab http://100.x.x.x:3000/ is open in Topic A with draft-a in its form. You open Topic B and the same Tab. B gets a new page with an empty form. Back in A, draft-a is still there. The key is (Host, owner, Tab URL): findLivePage, live-pages.ts:57. The screen files a page under the owner that the Attach holds when the Tab is shown (ownerOf, web-view.tsx:41). A cold start uses the Last Place's owner (web-view.tsx:85–88).

Separate pages, not a separate browser. Cookies and localStorage stay in the shared persistent web data store (ADR 0017). Only form text, sessionStorage and page script state are kept per Topic.

5 · Four choices go further than the request; each has a reason

  • A new native dependency, react-native-teleport (package.json, pnpm-lock.yaml). An overlay above the navigator needs no native code, but the page would not move with the push and pop animations, and it would cover the cold start's Connection Screen and the load-failure message. A dev client built before this must be built again.
  • Pages of a Session with no Topic are released too when the Host no longer has the Session. This matches the release of Topic pages, and without it a renamed Session's pages would never be released.
  • A Tab gone from the Host releases its page. The Place already forgot such a Tab. The request did not name this case.
  • No limit on the number of pages. Each page is one WKWebView in memory until a release.
